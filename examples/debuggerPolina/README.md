# Contents
- `debugger.py` contains a Python debugger that automates the manual debugging process that must now occur.
- The `ex1` directory contains a very simple example that demonstrates how the SMTCoq checker works, and how the current debugging process works.

# Usage
- To use `debugger.py`, you must first have an existing `.smt2` file and an existing `.pf` file with the same name. 
- For example, if the name of the `.smt2` file is `foo.smt2`, then the `.pf` will be `foo.pf`.
- Please make sure that the names are exactly the same since the filenames are key sensitive. 
- Note the complete path to the `.smt2` and `.pf` files. They should be in the same directory. Lets represent the path as `/path/to/files/foo.smt2 (or .pf)`
- In the terminal change your current directory to `debuggerPolina`, do this by running 
```
cd smtcoq/examples/debuggerPolina
``` 
- Note the exact location
- Finally, in the debuggerPolina/ directory, run
```
make ARGS=/path/to/files/foo
```

# Results
- Running this script will automatically generate a `(foo)run.v` and (foo).txt file in the `/path/to/files/` you gave the program.
- The `.v` file will contain will contain the program run by coqc. It can be ignored unless needed.
- The `.txt` file will contain a simplified version of the coq output that can be used to debug.
- The `.txt.` file will have comments formatted like this:
```
(*  Print nclauses. *) (* 2 *)
```
- Each coq comment is enclosed in a set of `(*` and `*)`
- Following the nclauses, conf, number of certificates and sanity check, all of the states and corresponding steps will be displayed in order.  

# Examples
Each of the `exi` (where `i` is a number) folders in this directory contain an example including:
- `exi.smt2`: the SMT file that asserts a formmula.
- `exi.pf`: the proof file that proves the formula.
- `exi.v`: the Coq file that calls SMTCoq's checker on the SMT
and proof files.
- `exidebugManual.v` (possibly): a manual debug file which the 
script should immitate.
- `exirun.v` a debug file that is generated by the script.
- `exi.txt` a text file with all the coq comments generated by the script.
## ex1
A very simple example that proves a Boolean formula with no examples.

## ex2
A simple example that proves a formula over integer variables
and functions.

## ex3
An example that shows an unsound step. This is not the perfect toy example, but its the closest
I can seem to get. Turns out its really hard to manufacture an unsound certificate that the 
SMTCoq parser will accept since the OCaml code does so much correctness checking.
The `ex3` files show a sound instance of the certificate, and the `ex3unsound` files show
an unsound instance of the certificate. Notice the difference between the `t2` step in 
`ex3.pf` and `ex3unsound.pf` - this is the only source of unsoundness. If you generate the debugging
file for the unsound example, you will see that the checker fails and that it particular fails
in the final step (`t3`) of the proof.

## ex4
This can be ignored for this project. This is just an example I ran into that shows that the checker
for the `tautology` rule is currently unsound.
